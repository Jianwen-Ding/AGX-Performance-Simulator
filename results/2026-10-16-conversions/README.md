# Exhaustive / edge-dense `convert` recordings (safe-01 part 1)

- **What was recorded:**
  - 80 forms: modes 0, 1 and 4-11, round field 0 (float → int) and 1 (int → float), 16- and 32-bit destination and
    source. These are exactly the encodings recorded `safe` in `coverage/expected/alu/convert_*`.
  - 1,372,198,046 hardware words in all (`scripts/record_convert.py`, inputs regenerated by `form_inputs`).
  - Each 2^18-lane chunk ran twice and agreed. Before any GPU run, each form's kernel passed an `agx_run` check
    against the model on ~12k sampled inputs (`record_convert.sim_gate`).
- **Result:** the simulator's `fsem::convert` model (numpy replica: `convert_check.model`) matches every word.
  `make verify-conversions` replays the retained samples (`hw_samples.json.gz`) through `agx_run` with the exact
  recorded kernels. When the full scratch data exists, it re-hashes it and re-checks every input.
- **Semantics and PTX mapping:** playground `novel-results/2026-10-16-conversions`.

Recorded 2026-10-16. 41 forms were recorded before the 18:09 GPU stall, which had a different cause (a bare-body
float-edge kernel; playground `notes/failed-approaches.md`). The other 39 were recorded at 19:05-19:10. AC power.
